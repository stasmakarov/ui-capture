# Задание для Cursor Agent: этап M2 — Jmix-бэкенд платформы ui-capture

Репозиторий: ui-capture (монорепо), ветка main, текущая версия 0.5.0.
Перед началом прочитай docs/platform-plan.md и README, изучи структуру: lesson-schema/, player/, studio/ (Node, локальный сервер 127.0.0.1:44731), student-portal/ (заглушка), platform-backend/ (заглушка), studio/macos/ (каркас URL-схемы uicapture://).

Коммить промежуточные результаты по ходу работы, чтобы при сбое ничего не потерялось.

## Что сделать

1. **Бэкенд в platform-backend/**: Jmix 2 (Vaadin Flow), PostgreSQL. Для разработки — docker-compose.yml с Postgres.
2. **Роли**: admin, reviewer, trainer, student. Ресурсные и row-level роли Jmix. Демо-пользователи создаются при старте в dev-профиле.
3. **Сущности**:
   - Lesson — заголовок, автор, текущий статус.
   - LessonVersion — неизменяемая. Хранит lesson.json в JSONB, проекцию шагов StepRef, файлы пакета в Jmix FileStorage.
   - LifecycleTransition — журнал переходов: кто, когда, из какого статуса, в какой, комментарий.
   - StudioToken — токен студии: владелец, хэш, срок, отозван ли.
   - Course и CourseRevision — минимальные заглушки под M3.
4. **REST-приём пакета**: `POST /api/lessons/import` принимает `.lesson.zip` и создаёт черновик.
   - Пакет содержит manifest.json с SHA-256 каждого файла, lesson.json, screens/, original/, assets/, audio/.
   - Хэши проверить; при несовпадении ответить 400 с понятной ошибкой.
   - Авторизация через StudioToken в заголовке Bearer.
   - Повторная загрузка того же урока создаёт новую LessonVersion.
5. **Сервис жизненного цикла урока**: draft → review → published → archived, возврат из review в draft с комментарием.
   - Самоутверждение разрешено: trainer может сам перевести свой урок в published.
   - Каждый переход пишется в LifecycleTransition.
6. **Экраны Vaadin**:
   - список уроков с фильтром по статусу;
   - карточка урока: версии, журнал переходов, кнопки переходов;
   - предпросмотр — отдаёт trainer.html из пакета в iframe;
   - экран «Мои токены студии»: выпустить токен (показать один раз), отозвать.
7. **Кнопка «Записать в студии»** на списке уроков.
   - Открывает `uicapture://new?course=<id>&server=<baseUrl>&ticket=<одноразовый тикет>`.
   - Запасной путь: если схема не сработала, страница пингует http://127.0.0.1:44731 и открывает студию там, передав server и ticket.
   - Тикет одноразовый и короткоживущий; студия обменивает его на StudioToken.
8. **Сторона студии (studio/)**:
   - принимать server и ticket, обменивать тикет на токен, хранить токен локально;
   - кнопка «Опубликовать на сервер»: собрать .lesson.zip (существующая команда package) и отправить в `/api/lessons/import`.
9. **Тесты**:
   - существующие 30 тестов должны проходить;
   - добавить тесты бэкенда: импорт, проверка хэшей, переходы ЖЦ, права ролей;
   - e2e: студия публикует пакет, урок появляется в админке черновиком.
10. **Скриншоты** новых экранов сохранить в docs/screens/m2/.
11. **README на русском**: как поднять dev-окружение (`docker compose up -d`, запуск Jmix), демо-логины, как связать студию с сервером.
12. **В docs/platform-plan.md** заменить оценки в неделях на реалистичные часы работы агента.
13. **Версию** поднять до 0.6.0.

## Готово, когда
- `./gradlew build` в platform-backend/ проходит;
- приложение стартует с Postgres из docker compose;
- trainer входит в админку, жмёт «Записать в студии», записывает урок, публикует, видит черновик и переводит его в published;
- все тесты зелёные, скриншоты лежат в docs/screens/m2/.
