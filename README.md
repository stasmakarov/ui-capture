# uitrainer

Проверка гипотезы: из записи работы в живом веб-приложении можно автоматически собрать интерактивный урок, которому нужна только лёгкая ручная правка.

Плеер не запускает систему-источник. Экран — это статическая страница (DOM без скриптов) или скриншот с прямоугольниками. Один и тот же `lesson.json` обслуживает оба режима.

## Что уже записано

Портал `zakupki.gov.ru` из этой среды недоступен: TCP-соединение устанавливается, TLS-рукопожатие обрывается по таймауту. Поэтому демонстрационный сценарий «найти карточку и открыть вкладку» снят с публичной Википедии, а второй урок — с другого сайта, SPA TodoMVC.

| Урок | Сайт | Экраны | Шаги |
| --- | --- | --- | --- |
| Найти статью и открыть вкладку | ru.wikipedia.org | 4 | 4 |
| Добавить задачи и переключить фильтр | demo.playwright.dev/todomvc | 5 | 4 |

Оба урока лежат в `lessons/` и открываются в плеере без повторной записи.

## Установка на Mac

Нужны Node.js 22 и Chromium. Apple Silicon и Intel — один и тот же порядок. После установки утилита работает офлайн: браузер не шлёт телеметрию Playwright, уроки собираются на диске.

Репозиторий лежит в Cursor Origin, не на GitHub: https://cursor.com/codebase/stanislav-makarov/ui-capture

```bash
# Node 22
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
# откройте новый терминал
nvm install 22
nvm use 22

git clone https://cursor.com/codebase/stanislav-makarov/ui-capture.git ui-capture
cd ui-capture
npm install
npx playwright install chromium
```

Проверка, что команда на месте: `npx uitrainer --help`.

Студия — локальная страница, с которой удобнее записывать, чем из терминала:

```bash
npm start
# или
npx uitrainer studio
```

Откроется браузер на `http://127.0.0.1:44731/`. Дальше: «Новый урок», адрес портала, название, режим захвата. «Разрешить микрофон» запрашивает доступ и показывает настоящие названия устройств; полоска уровня должна двигаться, когда вы говорите. Выбранный микрофон запоминается. Список «Браузер для записи»: встроенный Chromium, Google Chrome, Яндекс Браузер или другой путь. Если сайт не открывается из-за сертификата (российские сертификаты ГОСТ), выберите Яндекс Браузер. «Начать запись» открывает сайт отдельным окном. Говорите комментарий вслух: аудио режется по шагам и играет в режиме «Покажи». Кнопка «Скачать модель речи» показывает проценты и мегабайты и после загрузки пишет «Модель установлена» — то же при следующем запуске, если модель уже на диске. Команда `npx uitrainer whisper-download` качает ту же модель. Без модели запись всё равно сохраняется.

«Стоп» собирает урок и открывает просмотр. В «Править шаги» слева список шагов, справа поля выбранного шага. Порядок меняется стрелками и перетаскиванием. «Скачать trainer.html» собирает выбранные уроки (или все) в один файл, его открывают двойным щелчком. Аудио внутри файла. «Пакет» скачивает `.lesson.zip` для будущей публикации на платформу. «Импорт .lesson.zip» кладёт урок обратно в каталог.

Команды терминала `npx uitrainer <url>` и `npx uitrainer pack` из версии 0.2.0 на месте.

## Каталоги

Репозиторий — npm workspaces. Запуск студии не изменился: `npm start` из корня.

| Каталог | Зачем |
| --- | --- |
| `lesson-schema/` | Схема урока. Исходник — `src/lesson.ts`, JSON Schema — `schema/lesson.schema.json` (`npm run schema`) |
| `player/` | Плеер (Покажи / Попробуй / Проверь) |
| `studio/` | Экран студии. Сервер и запись — в `tools/` |
| `student-portal/` | Заготовка портала ученика (M3) |
| `platform-backend/` | Заготовка Jmix (M2), не npm |
| `lessons/` | Уже записанные уроки, их открывает и студия, и плеер |
| `tools/` | CLI, запись, сборка, пакет |

Пакет урока:

```bash
npx uitrainer package najti-statyu
npx uitrainer import ./lessons/najti-statyu.lesson.zip --out ./lessons
```

Внутри архива `manifest.json` (SHA-256 каждого файла), `lesson.json`, `screens/`, `original/`, `assets/`, `audio/`. Каталоги `compare/` и `replay/` в пакет не входят. План платформы — `docs/platform-plan.md`.

## Запись zakupki.gov.ru

Сайт должен открываться с вашего российского IP, без VPN. Встроенный Chromium не умеет TLS по ГОСТ. Если окно браузера не открывает портал, а в терминале ошибка про SSL или сертификат, запустите запись через Яндекс Браузер или Chrome, где сайт у вас уже открывается:

```bash
npx uitrainer "https://zakupki.gov.ru/epz/main/public/home.html" \
  --lesson-name "Найти извещение" \
  --executable-path "/Applications/Yandex.app/Contents/MacOS/Yandex"
```

Обычный запуск, если портал открывается в Chromium:

```bash
npx uitrainer "https://zakupki.gov.ru/epz/main/public/home.html" \
  --lesson-name "Найти извещение" \
  --out ./lessons
```

То же после клонирования: `npm run capture -- "https://zakupki.gov.ru/epz/main/public/home.html" --lesson-name "Найти извещение"`.

Что делать в окне браузера:

1. На главной введите в поиск номер или ключевое слово извещения.
2. Откройте результаты и карточку извещения.
3. Переключите вкладки карточки (общая информация, документы, журнал).
4. Подождите секунду после последнего действия и закройте окно браузера. Либо нажмите Ctrl+C в терминале.

Клики, ввод и переходы пишутся сами. Отдельно нажимать «запись экрана» не нужно.

Куда кладётся результат:

- урок: `lessons/najti-izveshenie/` (`lesson.json`, экраны, скриншоты);
- один файл тренажёра: `lessons/trainer.html` — откройте двойным щелчком, сервер не нужен;
- сырая запись (чтобы пересобрать): `captures/najti-izveshenie/`.

Имя папки — латиница из `--lesson-name`. Кириллический заголовок остаётся в каталоге урока, а папка получает короткий код.

В тренажёре те же режимы: **Покажи**, **Попробуй**, **Проверь**, переключатель **Разметка / Скриншот**.

Несколько записей собираются в один файл заново:

```bash
npx uitrainer pack --out ./lessons --html ./lessons/trainer.html
```

Если страница на canvas или с электронной подписью и повтор разметки пустой, пишите сразу скриншотами:

```bash
npx uitrainer "https://zakupki.gov.ru/epz/main/public/home.html" \
  --lesson-name "Найти извещение" \
  --mode screenshot \
  --executable-path "/Applications/Yandex.app/Contents/MacOS/Yandex"
```

`--mode auto` (по умолчанию) оставляет разметку, если повтор похож на оригинал, и сам включает скриншоты, если сходство ниже 85%.

## Платформа (M2): админка Jmix, публикация из студии

С версии 0.6.0 в `platform-backend/` лежит сервер платформы: Jmix 2.8 (Vaadin Flow) + PostgreSQL. Тренер записывает урок в студии, жмёт «Опубликовать на сервер», а в админке урок появляется черновиком. Дальше преподаватель публикует черновик сам. Отправка на проверку необязательна: проверяющий публикует урок из очереди или возвращает его в черновик с комментарием. Автор может опубликовать свой урок и пока он «на проверке». Опубликованный урок можно убрать в архив. Каждый переход пишется в журнал.

### Поднять dev-окружение

Нужны Docker, JDK 21 (Temurin) и Node 22.

```bash
docker compose up -d                 # PostgreSQL 16 на localhost:5432, база/логин/пароль uicapture
cd platform-backend
./gradlew bootRun --args='--spring.profiles.active=dev,local'
# админка: http://localhost:8090 (первый запуск собирает фронтенд Vaadin, это 1–2 минуты)
```

В профиле `dev` при старте создаются демо-пользователи и демо-курс. Пароль у всех совпадает с логином. После входа открывается кабинет роли, а не общий список. Если ролей несколько, приоритет такой: администратор → директор → преподаватель → проверяющий → ученик.

| Логин | Пароль | Роль | Куда попадает |
|---|---|---|---|
| `admin` | `admin` | администратор | Кабинет платформы: преподаватели, пользователи и роли, очередь проверки. Токены студии — в «Администрировании» |
| `trainer` | `trainer` | преподаватель | Свои курсы и счётчики уроков. «Записать в студии» — в карточке курса. Общего списка «Уроки» и токенов нет |
| `trainer2` | `trainer2` | преподаватель | Второй преподаватель: видит только свои курсы, не курсы `trainer` |
| `reviewer` | `reviewer` | проверяющий | Очередь приёмки. «Курсы» — справочник только для чтения. Создавать курсы и записывать в студии нельзя |
| `director` | `director` | директор | Все преподаватели и число курсов, курсы только для чтения. Роли, токены и запись в студии недоступны |
| `student` | `student` | ученик | Список опубликованных уроков. Черновиков, проверки, токенов и админки нет (портал — позже) |

У `trainer` в демо-курсе уже есть черновик, опубликованный урок, урок на проверке и возвращённый черновик. Это строки без файла студии, поэтому предпросмотр пустой.

Профили: `dev` — демо-данные, автосоздание БД, подсказка логина; `local` — личные переопределения из `application-local.properties` (файл в `.gitignore`, образец — `application-local.properties.example`). Для IDE включайте `dev,local`. На сервере профили `dev`/`local` не включают: только переменные `UITRAINER_DB_URL`, `UITRAINER_DB_USER`, `UITRAINER_DB_PASSWORD`, `UITRAINER_FILES_DIR`, `UITRAINER_PUBLIC_URL`, `UITRAINER_STUDIO_*`, `PORT`.

Без Docker подойдёт любой PostgreSQL 16. Адрес задаётся переменными `UITRAINER_DB_URL` (например `jdbc:postgresql://localhost:5432/uicapture?stringtype=unspecified`), `UITRAINER_DB_USER` и `UITRAINER_DB_PASSWORD`. Имя базы по умолчанию остаётся `uicapture`. Файлы пакетов хранятся в Jmix FileStorage, каталог задаёт `UITRAINER_FILES_DIR` (по умолчанию `platform-backend/.jmix/files`). Если сервер стоит за прокси, укажите его внешний адрес в `UITRAINER_PUBLIC_URL`: этот адрес попадает в ссылку для студии.

Сборка и тесты бэкенда (для тестов нужна база `uicapture_test` того же пользователя, её адрес задаёт `UITRAINER_TEST_DB_URL`; тесты не читают `application-local.properties`. Другой логин/пароль для тестов — через `UITRAINER_DB_USER` / `UITRAINER_DB_PASSWORD`):

```bash
cd platform-backend && ./gradlew build
```

### Связать студию с сервером

1. Запустите студию: `npm start` (http://127.0.0.1:44731).
2. Войдите в админку преподавателем (`trainer` / `trainer`). Откройте курс в кабинете или в «Курсах» и нажмите **«Записать в студии»**. Общего списка уроков у преподавателя нет.
3. Админка выпускает одноразовый тикет. Он живёт 5 минут и годится для одного обмена. Затем админка открывает `uitrainer://new?course=…&server=…&ticket=…`. Если схема не зарегистрирована (описана в `studio/macos/`), админка пингует `http://127.0.0.1:44731` и передаёт то же задание запущенной студии. Если студия не отвечает, админка показывает инструкцию и ссылку.
4. Студия обменивает тикет на персональный токен студии (`POST /api/studio/exchange`). Токен хранится в `lessons/.studio-platform.json` с правами 0600, в git этот файл не попадает. В шапке студии появляется строка «Платформа: …».
5. Запишите урок как обычно. Затем в карточке урока нажмите **«Опубликовать на сервер»**. Студия соберёт `.lesson.zip` (с `trainer.html` для предпросмотра) и отправит его в `POST /api/lessons/import`. В админке урок появится черновиком. Повторная публикация того же урока создаёт новую версию.

Без админки (например, на другой машине):

```bash
npx uitrainer open-url "uitrainer://new?course=…&server=http://localhost:8090&ticket=uictk_…"
# или токен, выпущенный администратором в «Администрирование → Мои токены студии»:
npx uitrainer platform-login http://localhost:8090 --token uicst_…
npx uitrainer publish spisok-zadach
```

Потерянный токен отзывается на экране «Мои токены студии». После отзыва студия с этим токеном получает 401.

### REST для студии

| Запрос | Что делает |
|---|---|
| `POST /api/lessons/import` | `.lesson.zip` в теле (`application/zip`) или в multipart-поле `file`. Заголовки: `Authorization: Bearer uicst_…` и необязательный `X-Course-Id`. Ответ 201 с `lessonId` и `versionNo`. Ответ 400, если хэш или размер не совпадает с `manifest.json`, в архиве есть лишний файл или нет файла, на который ссылается урок. Ответ 401 без токена или с отозванным токеном, 403 при попытке загрузить чужой урок |
| `POST /api/studio/exchange` | `{"ticket":"uictk_…"}` → `{token, username, courseId, courseTitle}`. Второй обмен того же тикета и просроченный тикет → 403 |
| `GET /api/studio/whoami` | проверка токена |

### Сквозной тест и скриншоты

```bash
# бэкенд запущен в профиле dev на :8090, порт студии 44731 свободен
UITRAINER_PLATFORM_URL=http://localhost:8090 UITRAINER_SCREENS_DIR=docs/screens/m2 \
  npx vitest run tools/studio/platform.e2e.test.ts
```

Сценарий теста: тренер жмёт «Записать в студии», студия получает тикет по запасному пути, затем «Опубликовать на сервер» → урок в админке черновиком → «Опубликовать» без проверки → «Опубликован» → предпросмотр `trainer.html` → выпуск токена. Кнопка «Отправить на проверку» на карточке черновика остаётся. Без `UITRAINER_PLATFORM_URL` тест пропускается, поэтому `npm test` не требует сервера. Скриншоты экранов M2 лежат в [`docs/screens/m2/`](docs/screens/m2/).

## Частые проблемы

- **SSL, сертификат, cipher, таймаут на zakupki.gov.ru.** Это TLS по ГОСТ. В студии выберите «Яндекс Браузер» в списке «Браузер для записи». Из терминала добавьте `--channel chrome` или `--executable-path` к Яндекс Браузеру (путь выше). Chrome с КриптоПро тоже подходит.
- **`Executable doesn't exist`.** Не установлен браузер Playwright: `npx playwright install chromium`.
- **Иконки пустые.** В урок попадают CSS, шрифты и картинки, которые браузер успел скачать во время записи. То, что сайт рисует только скриптом после снимка, в тренажёр не попадает — для такого экрана используйте `--mode screenshot`.
- **Последний шаг потерялся.** Закройте браузер через секунду после действия, не в ту же секунду.
- **Нужен Node 22.** `node -v` должен показать v22. Если нет — `nvm install 22 && nvm use 22`.

## Один файл, без сервера

Готовый плеер — один HTML, его можно открыть двойным щелчком. Внутри уроки Википедии и TodoMVC: скрипты, стили, `lesson.json`, экраны и картинки записи. Экраны показываются через `iframe` с `srcdoc`, картинки — как `data:`.

Как открыть:

1. Возьмите файл `artifacts/ui-trainer-wiki.html` (около 11 МБ).
2. Дважды щёлкните по нему или в Chrome, Edge или Firefox выберите «Открыть файл». Адрес будет вида `file:///…/ui-trainer-wiki.html`. Сервер не нужен, архив распаковывать не нужно.
3. В каталоге нажмите «Открыть урок» у «Найти статью и открыть вкладку».
4. **Покажи** проигрывает четыре шага сам. **Попробуй**: введите `извещение о закупке`, нажмите «Найти», откройте карточку «Единая информационная система в сфере закупок» и вкладку «Обсуждение». Неверный ввод даёт русскую ошибку.
5. Второй урок в том же файле — «Добавить задачи и переключить фильтр».

Пересобрать файл:

```bash
npm run pack:html
```

Мелкие иконки Википедии, которых не было в записи (`/w/…`), с диска не подгружаются. Снимки экранов и скачанные картинки внутри файла.

## Запись и сборка урока

Нужен браузер Playwright:

```bash
npx playwright install chromium
npm run capture -- najti-statyu
npm run build:lessons -- najti-statyu
```

Без аргумента обрабатываются все сценарии из `tools/capture/scenarios.ts`.

- `npm run capture` пишет в `captures/<id>/`: снимок rrweb (`rrweb-snapshot`), замороженный HTML, скриншот вьюпорта 1280×800, журнал действий и скачанные ресурсы.
- `npm run build:lessons` собирает самодостаточные экраны, ставит `data-hotspot`, выбирает более похожий на оригинал вариант (rrweb или заморозка DOM) и пишет `lessons/<id>/lesson.json`.

Проверка плеера сценарием (сервер `npm run dev` уже запущен):

```bash
npx tsx tools/verify/shots.ts
```

## Режимы плеера

- **Покажи** — шаг выполняется сам, цель подсвечивается.
- **Попробуй** — ученик действует сам; после двух ошибок показывается подсказка.
- **Проверь** — без подсказок, в конце оценка.
- **Разметка / Скриншот** — один урок, два способа показа.

Жёлтая полоса «Учебный тренажёр» не скрывается.

## Формат урока

Схема — `shared/lesson.ts`, версия `schemaVersion: 1`. Экран хранит и HTML, и скриншот, и hotspot с селектором и рамкой. Шаг ссылается на `hotspotId` и не зависит от способа отрисовки. Поля `hint` и `errorText` в черновике пустые: плеер подставляет русские тексты, пока преподаватель их не заполнит.
